# DMATool - Project Architecture

## Overview
DMATool is a professional DMA hardware interface tool for FPGA detection, DNA ID extraction, firmware flashing, and performance benchmarking.

## Technology Stack

### Frontend
- **ImGui** - Immediate mode GUI library
- **GLFW** - Window/input management
- **OpenGL3** - Graphics rendering
- **Custom Theme** - DMA Kings brand colors (Gold: #D4AF37, Dark: #0A0A0A)

### Backend
- **OpenOCD** - JTAG interface and FPGA communication
- **PowerShell** - Windows driver management
- **WinAPI** - System operations (clipboard, UAC, device management)

### Build System
- **Visual Studio 2022** - C++17 standard
- **CMake** (optional) - Cross-platform build support

## Key Components

### Backend::OpenOCDInterface
**Purpose:** FPGA detection, DNA extraction, driver management

**Key Methods:**
- `DetectFPGA()` - Main FPGA detection entry point
- `CheckCH347Driver()` - Query driver status via PowerShell
- `InstallCH347Driver()` - Automated driver installation
- `UninstallCH347Driver()` - Automated driver uninstallation
- `ParseOpenOCDOutput()` - Extract IDCODE and DNA from OpenOCD output
- `ExtractEmbeddedResource()` - Extract files from .exe resources

## Threading & Async Operations

### Current Approach: Synchronous
- All operations run on main thread
- UI updates every frame (ImGui immediate mode)
- Sleep() used for delays (Windows driver updates)

### Frame-Based Delays
```cpp
static int s_FramesSinceDetectionQueued = 0;

// Wait 2 frames before executing operation
if (s_FramesSinceDetectionQueued >= 2) {
    // Perform operation
}
```

**Why 2 frames?**
1. Frame 1: Show notification popup
2. Frame 2: Render popup again (stabilize UI)
3. Frame 3+: Execute operation while popup visible

## Error Handling

### Driver Installation Errors
```cpp
DWORD exitCode = 0;
GetExitCodeProcess(sei.hProcess, &exitCode);

if (exitCode == 0) {
    // Success
} else if (exitCode == 259) {
    // Driver already in store
} else if (exitCode == 2) {
    // File not found
} else {
    // Generic error
}
```

### OpenOCD Detection Errors
```
Error: unable to open ftdi device ? Driver not installed
Error: JTAG tap: xc7.tap not found ? No FPGA detected
Error: failed to open adapter ? Adapter not connected
```

## Performance Considerations

### Auto-Detection Timing
- **Driver Check:** ~500ms (PowerShell query)
- **OpenOCD Extraction:** ~100ms (one-time per session)
- **FPGA Detection:** ~2-3 seconds (OpenOCD execution)
- **Total:** ~3 seconds for complete auto-detection

### UI Responsiveness
- ImGui renders at 60 FPS
- Operations run synchronously (blocks UI)
- Floating notification prevents user interaction during operations
- Progress messages update every frame

## Security & Permissions

### UAC Prompts
Required for:
- Driver installation (`pnputil /add-driver /install`)
- Driver uninstallation (`pnputil /delete-driver /uninstall /force`)

### Administrator Privileges
**Recommended but not required:**
- ? Better for driver operations
- ? Reduces UAC prompts
- ? Not needed for FPGA detection (if driver already installed)
